上篇聊了冷热钱包，它们的共同点是——私钥在某个时刻一定是完整的。有没有办法从根上消掉这个单点？这篇聊 MPC 钱包。

**MPC 钱包的核心逻辑一句话：私钥从来不存在。**

不是藏在哪、不是加了密——是数学上根本没有「完整私钥」这个东西出现过。

这听起来反直觉。没有私钥，那交易是怎么签名的？往下看。

## 一、先从「单点故障」说起

不管是热钱包还是冷钱包，安全模型的底层都有一个共同前提：**存在一把完整的私钥**。

- 热钱包：私钥加密后存在手机/浏览器里，密码解密后使用
- 冷钱包：私钥存在不联网的硬件里，签名时才拿出来用

不管是哪种，**私钥在某一个时刻、某一个设备上，是完整的**。这就是单点——只要攻击者在那个时刻控制了那个设备，就能拿到私钥，资产就没了。

有没有办法从根本上消除这个单点？不是把私钥藏得更好，而是让它根本没有完整存在过？

这就是 MPC 要解决的问题。

---

## 二、MPC 是什么？

**MPC = Multi-Party Computation，多方安全计算。**

这个密码学概念不是为区块链发明的——它最早是姚期智在 1982 年提出的「百万富翁问题」：两个富翁想知道谁更有钱，但谁都不愿意透露自己具体有多少钱。MPC 让这件事成为可能：双方输入自己的财富数字，协议计算完只输出「谁更多」，各自的数字从头到尾没泄露。

用到钱包上，思路是这样：

| 传统钱包 | MPC 钱包 |
|---------|---------|
| 生成一把完整私钥 → 存起来 | 多个参与方各自生成一个**私钥碎片（share）**，完整私钥从未产生过 |
| 签名 = 用完整私钥对交易做 ECDSA | 签名 = 各参与方用各自的碎片做**协同计算**，生成一个完整签名 |
| 私钥泄露 = 资产全丢 | 单个碎片泄露 = 什么都没发生，因为一个碎片什么也干不了 |
| 保护私钥 = 保护一个东西 | 保护私钥 = 让多方的碎片不要同时被同一人拿到 |

**打个比方 🌰**

- 传统钱包像一把钥匙，谁拿到谁开门。可以把钥匙藏在枕头底下（热钱包）、锁在保险柜里（冷钱包），但钥匙还是那把完整的钥匙。
- MPC 钱包像三个守卫各自拿密码盘的一部分，开门需要至少两个人同时拧。每个人手上的东西单独拿出来就是一段乱码。而且这个「密码盘」从来不存在于任何一个守卫脑子里——它是三个人一起算出来的。

## 三、MPC 钱包是怎么工作的？

MPC 钱包依赖两个核心密码学协议：

### 3.1 分布式密钥生成（DKG — Distributed Key Generation）

这是**创建钱包**的阶段。

传统钱包的密钥生成：

```
生成随机数 → 私钥 → 公钥 → 地址
```

MPC 钱包的密钥生成：

```
参与方1 生成随机数 r1 ─┐
参与方2 生成随机数 r2 ─┼─→ 协同计算 → 公钥 + 每人持有一个碎片
参与方3 生成随机数 r3 ─┘
```

**关键：** 在这个过程中，完整私钥 = r1 + r2 + r3（简化表达），但每个参与方只知道自己的那一份，公钥才是唯一被公开的东西。整个过程中没有任何一方、在任何时刻、见到过完整的私钥。

**私钥就没有「出生」过。**

注意：这里说的不是 Shamir 秘密分享（SSS）那种「把完整私钥切成几份，要用时再拼回来」——那种方案拼的时候私钥会完整出现在内存里，单点依然存在。DKG 的不同在于：生成的碎片可以直接参与门限签名，签名过程中也不需要把私钥拼出来。完整私钥从头到尾不存在。

### 3.2 门限签名（TSS — Threshold Signature Scheme）

这是**签名交易**的阶段。

TSS 的核心参数是 `t-of-n`——n 个参与方中，至少 t 个协同才能完成签名。

以最常见的 **2-of-3** 为例：

```
用户的手机（碎片A）  ─┐
用户的电脑（碎片B）  ─┼─→ MPC 签名协议 → 一个有效的完整签名
服务商的服务器（碎片C）─┘   （任意2方参与即可）
```

流程：

1. 用户发起交易 → 手机用碎片 A 计算出一个「部分签名」
2. 服务器用碎片 C 计算出一个「部分签名」
3. 两边的部分签名在 MPC 协议里交换一轮消息
4. 组合成一个**看起来跟普通私钥签名一模一样**的签名
5. 广播到链上，矿工验证通过——链上根本不知道这是 MPC 签出来的

最终上链的是一个普通的 ECDSA/Schnorr 签名，跟传统钱包的签名没有区别。MPC 的神奇之处在于**生成这个签名的过程不需要完整私钥**，而不是签名的格式有什么特别。

## 四、深入一点：MPC 签名怎么做到「不需要完整私钥」？

ECDSA 签名的本质是用私钥 d 对消息哈希 z 做一个数学运算，输出 (r, s)。这个运算的核心步骤是：

```
s = k⁻¹(z + r·d) mod n
```

其中 k 是一次性随机数，d 是私钥。

下面用最常见的 **2-of-2** 方案说明原理；2-of-3 及以上用的是更复杂的门限 ECDSA 协议（如 GG20、FROST），思路一样——各方交换中间值但不泄露碎片，只是数学构造更复杂。

MPC 的思路是把 d 拆成 d₁ 和 d₂（d = d₁ + d₂），分别存在两个设备上。签名时：

1. 设备 1 用自己的 d₁ 和随机数 k₁ 算一部分
2. 设备 2 用自己的 d₂ 和随机数 k₂ 算一部分
3. 两边交换中间结果（不是 d₁、d₂ 本身），通过几轮交互
4. 最终的 s 被「拼」出来，等价于用完整私钥 d 签出来的结果

**交换的消息是加了掩码的**——比如传出去的是 d₁ 加上某个随机乱码，对方收到后只能用它完成计算，但推导不出 d₁ 是什么。

这就是 MPC 密码学的核心：**计算过程中交换的信息，不足以让任何一方反推出其他人的碎片。**

## 五、三个关键能力

除了基础的「碎片化私钥」，MPC 钱包还有几个很重要的能力：

### 5.1 密钥刷新（Key Refresh）

周期性地刷新每个参与方的碎片，但**不改变底层对应的公钥和地址**。

```
时间点 1: 手机碎片A₁ + 服务器碎片B₁ → 对应公钥 P
时间点 2: 手机碎片A₂ + 服务器碎片B₂ → 对应公钥 P（一样）
```

这么做的原因是：如果攻击者在很长一段时间内持续渗透，有可能慢慢收集到足够多的碎片。密钥刷新相当于定期把所有碎片「洗牌」，老的碎片直接作废——攻击者之前偷到的碎片变成废数据。

**这就像每隔一段时间换锁芯，但钥匙的齿形不变。** 这在传统钱包里做不到。

### 5.2 动态调整门限

机构级 MPC 方案（如 Fireblocks）支持随时调整 t-of-n：

- 资产量变大后，把 2-of-3 升级到 3-of-5
- 某个设备丢了，从 2-of-3 降级到 2-of-2（然后补一个新设备回到 2-of-3）
- 一个员工离职，撤销他持有的碎片

### 5.3 审批策略可编程

机构级 MPC 方案（如 Fireblocks）支持在碎片级别加审批规则：

- 单笔超过 10 万 USDC → 需要至少 3 个碎片参与
- 单笔低于 1000 USDC → 1 个碎片就够
- 市场开盘时段（比如下午 1:00–2:00 UTC 的自动交易）只要 2-of-3；其他时段需要 3-of-3

## 六、MPC vs 其他方案

### 6.1 MPC vs 传统单签钱包

| | 传统钱包（热/冷） | MPC 钱包 |
|---|---|---|
| 私钥是否存在过 | ✅ 完整私钥存在过 | ❌ 从未存在完整私钥 |
| 单点故障 | 有，私钥所在处就是单点 | 无，需多个碎片同时被攻破 |
| 恢复方式 | 助记词（丢了就没了） | 门限恢复（丢1个碎片可以补） |
| 链上兼容性 | 完全兼容 | 完全兼容（签名格式一样） |
| Gas 成本 | 正常 | 正常（签名格式一样） |

### 6.2 MPC vs 多重签名（Multi-sig）

这是最容易被混淆的一对。它们都提供「多因子」保护，但实现路径完全不同：

| | 多重签名（Multi-sig） | MPC 钱包 |
|---|---|---|
| 在哪实现 | **链上**，智能合约检查是否满足 N/M 签名 | **链下**，密码学协议生成一个单签名 |
| 链上可见 | 是，每笔交易包含多个签名 | 否，看起来就是一笔普通交易 |
| Gas 成本 | 高，每多一个签名就多一份数据 | 低，跟普通单签一样 |
| 隐私性 | 差，所有人都能看到这是多签地址 | 好，外人看不出是 MPC |
| 链依赖 | 重，需要链支持多签合约（比特币和以太坊的多签实现完全不同） | 轻，只要链支持 ECDSA/EdDSA 即可 |
| 审批策略 | 固定在合约里，改策略 = 换合约 | 灵活，链下调整即可 |
| 成熟度 | 高，链上验证，安全性经长时间检验 | 中高，安全性依赖 MPC 协议的密码学证明 |

一句话区分：**多签是链上逻辑，MPC 是链下魔法。**

多签的优势是「安全性由链保证」，合约写死了多少签名，就是多少签名。MPC 的优势是「灵活性」和「低成本」，但因为签名过程发生在链下，安全性依赖协议实现的正确性。

这俩不互斥——已经有方案在做「MPC 控制多签中的一把钥匙」，相当于是两层保护叠加。

## 七、市面上的 MPC 钱包

### 机构级

| 产品 | 特点 |
|------|------|
| **Fireblocks** | 机构 MPC 的事实标准，用的是自研的 MPC-CMP 协议。支持 50+ 链，提供完整的审批策略引擎。客户包括 BNY Mellon、Revolut 等 |
| **Copper** | 英国合规 MPC 托管方案，主打机构合规 |
| **Cobo MPC** | 新加坡团队，支持 MPC + 多签混合方案 |

### 消费者级

| 产品 | 特点 |
|------|------|
| **ZenGo** | 最早做消费者 MPC 钱包的之一。2-of-2 方案：手机一份碎片 + ZenGo 服务器一份碎片，任意一方挂掉了都能恢复 |
| **Coinbase Smart Wallet** | 2024 年推出，支持 MPC 模式，用手机安全区域 + Coinbase 服务器做 2-of-2 |
| **Binance Web3 Wallet** | 币安内嵌钱包，采用类似 2-of-2 架构，碎片分别存在手机和币安 |
| **OKX Wallet** | 类似 2-of-2 架构，手机 TEE + 服务器 |

消费者方案几乎都是 2-of-2 架构——自己持有一份碎片，服务商持有一份。这样即使服务商被黑，攻击者也只有一份碎片，什么都干不了。换手机的时候服务商协助恢复签名权——不需要记助记词。

不过 2-of-2 有个现实的权衡：服务商那一份碎片如果配合恶意用户或者出 bug，理论上可以做恶意签名。各家通常加审批规则来缓解——比如大额需要额外的活体检测、2FA、甚至人工审核。

## 八、MPC 有没有坑？

当然有，说清楚：

### 8.1 协调成本

MPC 签名需要多方在线交互。2-of-3 方案里，如果手机没电、服务器在维护、电脑断网刚好凑一起了，就签不了。实际使用中需要做好碎片的可用性规划——比如把两个碎片放在自己完全控制的设备上，第三个碎片放在服务商。

### 8.2 协议安全性

MPC 的安全性来自密码学证明，不是物理隔离。协议实现有 bug（比如随机数生成不够随机、中间消息的零知识证明没做对），就可能被攻击者利用。2023 年 Fireblocks 团队就曾披露过 GG18/GG20 等门限 ECDSA 协议实现中的安全漏洞（CVE-2023-33241），攻击者可在签名交互中逐步提取私钥碎片。

所以选 MPC 方案的时候，重点不是「是不是 MPC」，而是协议有没有经过第三方审计、有没有形式化验证。

### 8.3 恢复模型的隐形成本

消费级 2-of-2 MPC 方案主打「不用记助记词」。这确实是更好的体验——但代价是多了一个需要信任的实体：服务商在恢复流程中不能作恶。传统冷钱包只需要信任自己保管助记词的能力，MPC 多了一层外部依赖。

安全模型上没有免费的午餐。换回来的是体验的大幅提升——对于不想折腾硬件钱包的主流用户来说，这个取舍是划算的。

### 8.4 碎片管理

碎片也是数据，需要被存储和保护。如果碎片存在手机上（App 沙盒），手机丢了怎么办？如果碎片存在服务商那里，服务商被攻击了怎么办？好的 MPC 方案会：

- 碎片存在手机的 TEE/Secure Enclave 里，即使 root 也读不到
- 服务器碎片存在 HSM（硬件安全模块）里
- 定期做密钥刷新

但这个级别的保护不是所有 MPC 钱包都做到的。

## 九、所以 MPC 钱包适合谁？

| 场景 | 推荐程度 |
|------|---------|
| 不想买硬件钱包，想要比热钱包更安全 | ⭐⭐⭐⭐⭐ 非常适合，MPC 是热钱包的明显升级 |
| 管理几万到几十万美元的资产 | ⭐⭐⭐⭐ 适合，2-of-3 方案比单签热钱包安全得多 |
| 持有超百万美元、长期不动 | ⭐⭐⭐ 可以考虑，但硬件钱包 + 多签的「久经考验」优势还在 |
| 机构/团队管理资产 | ⭐⭐⭐⭐⭐ 非常适合，灵活审批 + 无单点 |
| 对技术有洁癖，不想信任任何第三方 | ⭐⭐ 不完全适合，大多数 MPC 方案都有服务商参与的碎片 |

---

## 十、总结

三句话：

1. **MPC 钱包用密码学手段消除了「完整私钥」这个单点故障**——私钥在数学意义上从未存在过，碎片分散在多处，签名靠协同计算
2. **跟多签的区别：多签是链上逻辑（多个签名），MPC 是链下魔法（多个碎片协同、产出一个签名）**——MPC 更省 Gas、更隐私、更灵活，但安全性依赖协议实现的正确性
3. **MPC 不是银弹**——更好的体验和更强的单点防护，代价是新的信任模型和协调成本。选什么方案，取决于资产规模、技术能力和信任偏好

回过头看开头那句话：**私钥从来不存在。** 这个想法本身就挺颠覆直觉的——大概也是密码学最迷人的地方。
