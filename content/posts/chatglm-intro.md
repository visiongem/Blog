最近准备开始学 LangChain，动手之前得先搞明白一件事：自己要「调」的模型到底是个什么东西。

LangChain 本质是把大模型当积木，接数据、接工具、接外部世界。但积木本身——这个模型——决定了应用能做什么、做得好不好。

如果做中文场景，那 ChatGLM 是绕不开的一个选项。今天先来了解下它吧。

> ChatGLM 跟 ChatGPT 不是「竞品复刻」的关系。它的底层逻辑是从中文出发的——这件事也许比想象的重要。

## 一、ChatGLM 是什么？

**ChatGLM 是智谱 AI（清华系团队）开发的中英双语大语言模型。**

几个关键信息：

| 项目 | 说明 |
|------|------|
| **开发方** | 智谱 AI（Zhipu AI），清华计算机系背景 |
| **基座** | GLM（General Language Model）架构，不是 GPT |
| **开源** | ChatGLM-6B 可以在消费级显卡上跑，完全开源 |
| **商用** | GLM-4 等更高版本通过 API 提供服务 |

> 这里简单说一下 GPT 和 GLM 架构的区别——外行也不需要深究，有个印象就行。

GPT 的训练方式很直观：给你前半句话，让你预测下一个词。就像老师指着课文说「你接着往下念」。这种叫**自回归（Autoregressive）**，方向是单向的，从左往右。

但 GLM 不这么干。它的思路是：**随机把一句话里的几个词挖掉，让模型填空。** 就像完形填空——模型需要同时看前后的内容，才能填对。

打个比方：

| 架构 | 怎么学 | 比喻 |
|------|--------|------|
| **GPT** | 给定上文，预测下一个词 | 老师让你「接着往下念」 |
| **GLM** | 挖掉中间的词，看前后推断 | 老师让你「把空填上」 |

两种方式各有各的好处。GPT 的方式更自然，生成文字特别流畅，所以 ChatGPT 聊天体验很好。GLM 的方式让模型天然就能理解上下文的关系——因为它训练时就在「看前看后」。

实际用起来，ChatGLM 在**理解一段话的含义、做分类、做摘要**这类任务上有结构上的优势；ChatGPT 在**自由对话和创意生成**上更顺手。当然到了 GLM-4 / GPT-4 这个级别，差距已经很小了，更多是训练数据和算力的差别。

时间线很简单：
- 2022 年：GLM-130B 发布，当时最大的中英双语开源模型
- 2023 年：ChatGLM-6B 发布，62 亿参数，一张 3060 就能跑
- 2024 年：GLM-4 发布，长上下文 + Agent 能力 + All-Tools 调用

**ChatGLM-6B 这件事影响很大。** 它证明了一件事：中文大模型不需要 A100 集群也能用。开发者在自己电脑上就能跑起来，这直接降低了中文 AI 应用的开发门槛。

Github 地址：https://github.com/zai-org/ChatGLM-6B

## 二、中文模型跟英文模型，到底差在哪？

这个问题很多人没想过。一个模型能不能说中文，不就行了？

不是的。差别在根上。

### 1. 训练数据：「顺便学的」vs「母语」

大多数英文大模型（LLaMA、GPT 系列）的训练数据里，中文占比通常在 **5% 以下**。它们能说中文，是因为大量多语言语料混在一起训练，中文是「顺带学会的」。

ChatGLM 从一开始就是中英双语训练，中文语料的质量和占比都远高于英文模型。

这意味着什么？一个例子：

你问一个英文模型「床前明月光下一句」，它能答对——因为这首诗在互联网上出现频率太高了。但你问它「老六是什么意思」或者「帮我写一封符合中国劳动法的离职通知」，差别就出来了。

### 2. 分词器：同样的中文，不同的切法

这是最容易被忽略、也最实在的差别。

大模型不能直接读文字。它要先做一件事：**把文本切成 token（词元）**。切得好不好，直接影响模型的理解能力。

举个例子。假设「今天天气真好」这句话：

- **英文模型的 Tokenizer**（比如 LLaMA 用的 SentencePiece）：中文不在它的优化范围内，可能会把每个字拆成 2-3 个 token，或者切成奇怪的片段。一句话下来 token 数是中文原生模型的 **1.5 到 2 倍**。
- **ChatGLM 的 Tokenizer**：中英文都经过专门优化，中文按语义切词，token 效率高得多。

**Token 多意味着什么？**
- 同样的上下文窗口，英文模型装的中文信息更少
- 同样的回答，英文模型消耗更多推理成本
- 切错的中文字会导致理解偏差——模型看到的不是「今天/天气/真好」，而是「今/天天/气真/好」这种碎片

### 3. 文化语境：翻译解决不了的事

成语典故、网络流行语、法律条文、行业术语——这些东西不是翻译的问题，是**训练数据里有没有**的问题。

一个中文模型比你更懂「意思意思」「懂的都懂」「挺好的」——这种模糊表达的判断能力，靠的是海量中文语料里泡出来的，不是翻几本词典能解决的。

## 三、学 LangChain 为什么要了解这个？

LangChain 做的事情，本质上就一句话：**把用户的输入、外部数据、工具和 LLM 串成一条流水线。**

```text
用户提问 → LangChain 编排 → 调数据库查资料 → 拼成 Prompt → 发给模型 → 拿回结果 → 后处理 → 返回用户
```

在这条流水线里，**模型是最后一棒，也是最重要的一棒。** 模型「听不懂」，前面所有工作白费。

如果应用是中文场景——比如客服机器人、文档问答、合同审查——那模型就得是「中文 native」的。用英文模型做中文应用，会遇到几个实际问题：

- **Token 浪费**：同样的中文对话，token 消耗翻倍 → 成本翻倍
- **理解偏差**：对中文的微妙表达判断不准
- **幻觉更多**：模型对不熟悉的语言，更容易胡编

**ChatGLM 在这个场景下的优势很直接：**
- 开源版可以本地跑，数据不出服务器
- API 版有中文优化的对话和工具调用能力
- LangChain 社区已经有 ChatGLM 的集成方案，接进去不费劲

所以学 LangChain 之前，先搞清楚要调哪个模型——这件事不是「以后再说」，而是决定了后面怎么写 Prompt、怎么设计 Chain、怎么控制成本。

## 四、一句总结

ChatGLM 不是一个「ChatGPT 的平替」。它做的是同一类事——大语言模型——但它是从中文的土壤里长出来的。

对学 LangChain 的人来说，知道这个就够了：**模型不是你随便选一个就行的。选对模型，后面的工作少一半。**

今天前置 AI 学习就到这了，明天要正式开始 LangChain 的实践学习了。
