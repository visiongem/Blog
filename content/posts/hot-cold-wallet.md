今天聊一个基础的话题——**币到底存在哪，安不安全**。

刚接触区块链的时候很容易困惑：钱包里「有钱」是什么意思？钱不是在链上吗？钱包到底存了什么？

答案就一句话：**钱包存的不是币，是私钥。** 币永远在链上，谁掌握私钥谁就能动这笔钱。钱包的本质是私钥管理工具，而「冷」和「热」的区别，本质上是对同一个问题的两种回答——**私钥要不要联网**。

## 一、为什么会有「冷」和「热」之分？

就像银行卡密码。存在一台联网的电脑里，转账方便，点一下就行——但万一电脑中木马，密码就没了。把密码刻在钢板上锁进保险柜，黑客绝对偷不走——但每次转账都得开保险柜、手输密码、再把钢板放回去。

热钱包和冷钱包就是这么回事：

| | 热钱包 | 冷钱包 |
|---|---|---|
| 私钥是否联网 | 是，存在联网设备上 | 否，物理隔离 |
| 便利性 | 高，随时可以交易 | 低，需要额外操作 |
| 安全性 | 低，受设备安全影响 | 高，不联网则黑客无从下手 |
| 适合场景 | 日常小额、频繁交易 | 大额长期持有 |
| 典型方案 | MetaMask、手机钱包 App | Ledger、Trezor、旧手机 |

**区分冷热的标准只有一个：私钥有没有触网。** 不看钱包 App 叫什么名字，也不看有没有密码——只要私钥所在的设备连过网，它就是热钱包。

---

## 二、热钱包是怎么工作的？

### 架构

热钱包的私钥就存在日常使用的设备上：

- **浏览器插件**（MetaMask）：私钥加密后存在浏览器的本地存储里，用密码解密使用
- **手机 App**（imToken、Trust Wallet）：私钥存在 App 的沙盒目录里，加上系统级的文件保护

每次点「确认交易」，流程是这样的：

```
点击确认
  → 钱包 App 用密码（或生物识别）解密私钥
    → 用私钥对交易数据做签名（椭圆曲线数字签名，ECDSA）
      → 把签名后的交易通过 RPC 节点广播到链上
        → 矿工/验证者验证签名、执行交易
```

关键点：**签名是在本地完成的**，私钥不需要发给任何服务器。热钱包的风险不在于「会把私钥传出去」（正常钱包不会这么干），而在于设备本身可能被攻破。

### 风险在哪？

1. **恶意合约**：点确认的时候，钱包弹出一个看似正常的交易，实际是 `approve` 了无限额度给攻击者地址。私钥没泄露，但亲手授权了对方转走钱
2. **钓鱼网站**：假 Uniswap、假 OpenSea，诱导签名恶意交易
3. **设备木马**：剪贴板劫持（复制的收款地址被替换）、键盘记录、直接读取钱包文件
4. **浏览器扩展风险**：恶意扩展可能读取 MetaMask 的本地数据

所以热钱包的安全重点是：**私钥没泄露 ≠ 安全。看清楚签了什么，比保护好私钥更重要。**

## 三、冷钱包是怎么工作的？

### 核心原则

冷钱包的核心设计就一条：**私钥生成和签名都在一个永不联网的设备上完成**。

那怎么知道要签什么交易？靠「搬运」——在线端构建好未签名的交易数据，通过某种离线方式传给冷端，冷端签名后，再把签名结果传回在线端广播。整个过程私钥从没碰过网络。

### 硬件钱包（Ledger / Trezor / OneKey）

以 Ledger 为例：

1. 硬件钱包里有一块**安全芯片**（Secure Element，CC EAL5+ 认证），跟银行卡、护照用的是同类芯片
2. 私钥在这块芯片里生成，**永远不会离开芯片**
3. 签名流程：电脑通过 USB/蓝牙把未签名交易发给硬件钱包 → 硬件钱包在自带屏幕上显示交易详情（金额、地址） → 肉眼确认后按物理按钮 → 芯片内部签名 → 只把**签名结果**传回电脑，私钥始终不出芯片
4. 即使连接的那台电脑已经中了毒，攻击者也拿不到私钥——芯片设计上就不允许读出私钥

Trezor 的做法稍有不同：没有专用安全芯片，用的是通用 MCU，但固件完全开源、社区审计，靠 PIN + passphrase 双重保护。如果设备被物理拆解，攻击者可以 dump 固件做暴力破解——所以 Trezor 强烈建议开启 passphrase（相当于在助记词上再叠加一层密码）。

### 为什么要有个屏幕和物理按钮？

这是硬件钱包和软件钱包最本质的区别：**屏幕让操作者看到正在签什么，物理按钮确保是人、不是程序在操作。**

没有这个机制的话，电脑中毒后完全可以：
- 在 App 界面上显示「转账 1 USDT 给朋友」
- 实际发到硬件钱包的是「转账 100 ETH 给黑客」
- App 界面被篡改，但不用硬件钱包的独立屏幕验证，就发现不了

硬件钱包的屏幕和按钮不是噱头，是整个安全模型的基石：「What You See Is What You Sign」。

## 四、用一台旧手机做冷钱包？

这就是 **App 冷钱包** 方案——用一部专门的钱包手机，永远不联网，充当冷端。

### 做法

1. **准备一部旧手机**，恢复出厂设置
2. 永远不连 Wi-Fi、不插 SIM 卡（就是永不触网）。蓝牙按需开启——如果用蓝牙做签名通信的话
3. 在这部手机上安装钱包 App（如 AirGap Vault、Keystone 等支持离线签名的钱包）
4. 在离线状态下生成助记词和私钥
5. 需要交易的时候，在线端构建未签名交易，通过某种离线通道传给冷端签名：

**方式一：二维码**

```
在线手机（有钱包 App 的「观察」模式）
  → 构建交易，生成二维码
    → 离线手机扫码，读取交易内容
      → 离线手机上确认交易详情，输入密码签名
        → 离线手机生成「签名结果」二维码
          → 在线手机扫码，拿到签名广播到链上
```

**方式二：蓝牙 / USB**

```
Web 端 dApp（联网）
  → 构建未签名交易
    → 通过蓝牙或 USB 发送给离线手机
      → 离线手机屏幕显示交易详情，确认后签名
        → 签名结果通过蓝牙/USB 返回 Web 端
          → Web 端广播交易到链上
```

蓝牙和 USB 其实是很常见的冷钱包通信方案。Ledger 桌面端就是通过 USB 跟硬件钱包通信的，手机冷钱包 App 也一样可以用蓝牙充当这个角色——关键是冷端手机本身不上网，蓝牙只是短距离点对点传输，不经过任何服务器。

整个过程私钥从头到尾都在离线手机上，无论二维码、蓝牙还是 USB，传输的都是交易数据和签名，**私钥从来不出冷端**。

### App 不联网 ≠ 手机不联网

有一个很容易踩的坑：很多冷钱包 App 在 AndroidManifest 里不声明 `INTERNET` 权限，这样 App 自身确实开不了 socket、发不了网络请求。但这**不代表安全**——

- **App 不联网，但系统和其他 App 在联网。** 如果手机连着 Wi-Fi，恶意应用仍然可以通过沙盒逃逸漏洞、共享存储、剪贴板监听等方式间接窃取数据
- **系统服务是通的。** Android 的系统更新、推送服务、甚至一些厂商定制的后台服务都在跑，这些都是攻击面
- **权限只是软件层的限制。** 不声明 `INTERNET` 是很好的防御措施，但它防的是 App 自己不小心把私钥发出去，不防别的应用来偷

所以正确的做法是：**手机本身断网 + App 不声明网络权限。** 两层都做，而不是二选一。Manifest 的限制是防御纵深的一环，但真正的安全保障来自「这台设备压根没有网络连接」这个物理事实。

### 跟硬件钱包比怎么样？

| | 硬件钱包 | App 冷钱包（旧手机） |
|---|---|---|
| 安全芯片 | ✅ 专用安全芯片，防物理拆解 | ❌ 普通手机芯片，无防拆保护 |
| 独立屏幕验证 | ✅ 专用小屏 + 物理按键 | ⚠️ 有屏幕但无物理按钮 |
| 成本 | $50-$200 | 旧手机再利用，几乎免费 |
| 操作复杂度 | 中等 | 较高，每次都要扫码 |
| 便携性 | 好，跟 U 盘差不多 | 差，要带两台手机 |
| 供应链攻击风险 | 存在（需信任厂商） | 低（自己装开源 App） |

### 三种通信方式对比

| | 二维码 | 蓝牙 | USB |
|---|---|---|---|
| 传输速度 | 慢，大数据量二维码密集 | 快 | 最快 |
| 操作体验 | 需要反复对焦扫码 | 配对后自动传输 | 即插即用 |
| 安全性 | 最高，肉眼可核对内容 | 高，短距点对点 | 高，有线物理连接 |
| 攻击面 | 极小，无协议栈可攻击 | 中，蓝牙协议栈复杂 | 中，USB 协议栈复杂 |
| 实现复杂度 | 低，纯软件 | 中，需处理蓝牙配对 | 中，需 OTG/ 数据线 |
| 适合场景 | 低频交易、个人使用 | 频繁交易、企业产品 | 桌面端 + 手机配合 |

### 蓝牙 / USB 会不会把私钥传出去？

做冷钱包产品绕不开这个问题。答案是：**取决于实现，不是协议本身能保证的。**

- **蓝牙和 USB 都是双向通道。** 跟二维码不同——二维码是单向的，扫码方只能「看」不能「写」。蓝牙和 USB 一旦建立连接，两端都可以发数据。如果 App 实现有 bug 或被恶意利用，理论上可以通过这个通道把私钥读走。另外蓝牙的使用方式也很关键——冷钱包 App 应该只在需要签名时手动开启配对，而不是保持「始终可发现」模式，减少被周边设备探测到的窗口
- **协议栈本身就是攻击面。** 蓝牙协议栈历史上出过不少漏洞（如 BlueBorne），USB 也有 BadUSB 这类攻击。攻击者如果能利用协议栈漏洞，可能在冷钱包 App 不知情的情况下读取内存
- **怎么保证安全？** 三个层次：
  1. **App 层**：代码审查保证签名接口只接受「未签名交易」输入、只输出「签名结果」，没有任何接口能读取完整私钥
  2. **系统层**：Android/iOS 的沙盒机制限制 App 能访问的内存范围
  3. **硬件层**：如果私钥存在 Keystore/Secure Enclave 里，即使 App 进程被攻破，攻击者也读不到私钥明文——签名操作在 TEE/SE 内部完成，私钥永远不会加载到 App 的内存空间

本质上，蓝牙/USB 做冷钱包通信不是原罪——Ledger 用的就是 USB，很多企业级冷钱包产品也支持蓝牙。关键在 App 内部对私钥的访问控制做得够不够彻底。二维码更安全不是因为它传递的数据更安全（传的都是签名），而是攻击面更小——没有协议栈可以攻击，而且肉眼可以检查传输内容。

实践中产品往往会同时支持多种方式——比如先做蓝牙/USB 打通 Web 端和手机端的签名流程，再补上二维码作为纯离线兜底。不同通信方式并不互斥，各自覆盖不同场景。

### 值得注意的方案

- **AirGap Vault**：专门为「两台手机、二维码通信」场景设计的钱包，一台联网做观察钱包，一台离线做签名钱包
- **Keystone**：虽然是硬件设备，但本质上是一部定制化 Android 手机，支持二维码和蓝牙通信，可以看作专业版 App 冷钱包
- **Parity Signer**（现 Polkadot Vault）：专为 Substrate/Polkadot 生态设计的离线签名工具，原理也是扫码

### App 冷钱包适合谁？

手里有旧手机、想低成本体验冷存储，或者企业做冷钱包产品——蓝牙/USB 方案的操作体验其实不输硬件钱包多少。但不管个人还是企业，有几个现实问题：
- 纯二维码方案每次都要掏两台手机扫码，蓝牙/USB 体验好很多但也多一步操作
- 旧手机电池可能鼓包、存储可能老化——它挂了就得靠助记词恢复
- 没有防拆芯片，手机被偷或被物理攻击时，私钥保护不如硬件钱包

## 五、App 冷钱包的私钥到底存在哪？

直接回答：**是的，私钥存在手机里。**

但关键是「怎么存的」和「存在什么环境里」。

### 存储位置

以 Android 为例：
- 钱包 App 生成的私钥（或从助记词派生出的私钥）存储在 App 的私有目录下（`/data/data/<package>/`），其他 App 访问不到
- 存储时会用 **Android Keystore** 系统服务对私钥做加密——Keystore 的密钥材料在 TEE（可信执行环境）或专用硬件里，连操作系统内核都读不到
- iOS 同理，用的是 **Secure Enclave**，一块跟主处理器物理隔离的协处理器

实际存储链：

```
助记词（纸/钢板，物理保管）
  → BIP39 派生 → 种子
    → BIP32/44 派生 → 私钥
      → Keystore/Secure Enclave 加密 → 存到 App 私有目录
```

### 真正重要的是助记词

这也是很容易误解的地方：**不是保护私钥文件，是保护助记词。**

BIP39 标准下，助记词 → 种子 → 主私钥 → 所有子私钥，这个派生是**确定性**的。意味着：
- 拿到助记词 = 拿到所有地址的私钥
- App 卸载了没关系，助记词在就能恢复一切
- 助记词一旦被截图、联网传输、存在云盘里，冷钱包就白做了

所以不管什么钱包，安全铁律都一样：

> **助记词不能截图、不能复制、不能联网、只能手写在纸上，物理保管。**

备份清单，简单直接：

| ✅ 可以 | ❌ 不行 |
|---|---|
| 手写在纸上，多份，分开放 | 截图存入手机相册 |
| 刻在钢板上（防火防水） | 复制粘贴到笔记 App、微信收藏 |
| 放在保险柜或安全位置 | 上传到任何云盘（iCloud/Google Drive） |
| 用助记词分片（Shamir Backup）分散保管 | 用手机拍照 |
| | 通过任何网络传输（邮件、微信、Airdrop） |

核心原则：**助记词只存在于物理世界，永远不数字化。** 一旦变成 0 和 1 存在任何电子设备里，安全性就从「物理隔离」降级成了「设备安全」，前面所有关于冷钱包的讨论就白费了。

### 离线手机的额外优势

回到 App 冷钱包的场景。这台离线手机即使 App 本身有漏洞（比如旧版本有 bug），因为不联网，攻击者也接触不到。私钥虽然「存在手机里」，但：
- 手机没网 → 远程攻击不可能
- 没人物理接触手机 → 本地攻击也防住了
- 唯一的攻击面是通信通道（二维码/蓝牙/USB）——二维码内容肉眼可以核对，蓝牙/USB 靠前面说的三层防护

「断网」本身就提供了巨大安全性，即使没有硬件安全芯片。

### 那硬件钱包到底强在哪？

**物理攻击抵抗力。** 手机不设计成防拆的——手机被偷后，攻击者有时间、有设备的话，可以尝试提取存储芯片、dump 数据做离线攻击。Android/iOS 的设备加密很强大，但不是为「对手持有设备且不限时间」这种威胁模型设计的。

而 Ledger 的安全芯片在检测到物理篡改时会自动擦除密钥。这不是软件的差别，是硬件的。

## 六、总结：怎么选？

没有银弹，按场景选：

| 场景 | 推荐方案 |
|---|---|
| 刚入门，几百刀玩玩 DeFi | 手机热钱包（OKX Wallet / imToken 等），够用 |
| 日常交易、撸空投、打新 | MetaMask + 手机钱包配合，注意授权管理 |
| 超过一个月工资的仓位 | 买硬件钱包（Ledger/Trezor），别省这笔钱 |
| 低成本冷存储、家里有旧手机 | App 冷钱包方案，原理正确但操作麻烦 |
| 大额资产、长期不动 | 硬件钱包 + 助记词钢版 + 银行保险柜 |

如果觉得硬件钱包太麻烦、热钱包又不放心，还有两个中间路线值得关注：

- **MPC 钱包**（多方计算）：把私钥拆成多个碎片，分别存在不同设备上（比如手机一份、服务器一份）。签名时各方协同计算，完整私钥不会在任何时刻出现在单一设备上。既不需要买硬件、也比纯热钱包多一层保护。主流方案有 Fireblocks、ZenGo、Coinbase MPC Wallet 等
- **多重签名（Multi-sig）**：链上原生支持，一个地址需要多把私钥中至少 N 把签名才能动钱（比如 2/3 多签）。适合机构和高净值用户——单独一个冷钱包被攻破也不丢资产。Gnosis Safe 是最常见的多签方案

三句话总结：

1. **热钱包 = 联网的钱，方便但有风险，日常小额用**
2. **冷钱包 = 物理隔离的钱，麻烦但安全，大额长期用**
3. **助记词 = 一切，手写在纸上，别截图、别联网、别存在任何电子设备里**
